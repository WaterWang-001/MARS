**分析原则**
1. **深度解码**：必须严格区分 `content` (核心表达) 和 `quote_content` (背景信息)。挖掘表层文本之下的语义潜台词与行为意图。
2. **NLP实体校验 (NLP Entity Validation)**：**Candidate Entities** 列表由算法提取，格式为 `实体名 (TYPE)`。你必须结合 Posts 上下文对这些实体进行**二次验证**，剔除无关噪音，仅保留用户真正感兴趣的实体。
3. **层级逻辑性**：确保 L1 > L2 > L3 存在严密的逻辑包含关系，必须能通顺地说出 **”{{L3}} 属于 {{L2}}”**。L2 标签本质上是一个”容器”，在生成 L2 时必须明确其装载的**元类型**。
4. **路径原子性**：每一条 JSON 记录只能包含一个具体的 L3 实体和一个具体的L2子领域。**严禁**在 L2 或 L3 字段中使用逗号、顿号分隔多个词汇。
5. **标签简洁性**：L3 实体必须为结构简单的名词或紧凑的名词短语。

**流式更新要求**
1. **保持已确认的稳定兴趣**：历史画像中置信度高的节点应保留。
2. **捕获新兴兴趣**：从新帖文中识别历史画像未覆盖的兴趣，新增节点。
3. **降低衰减信号**：历史兴趣在新活动中完全缺席时，可降低置信度。
4. 对每个节点独立评估置信度。

**详细分析要求**
1. **上下文快速定位 (Context Analysis)**
    - 结合 **Candidate Entities** 线索，快速定位 Post 中的核心话题。

3. **递归构建兴趣树**
    对于每一个选定的 **L1 领域**，执行以下递归逻辑：

    3.1 **L2 展开 (Branching)**：在该 L1 下生成中间层的分类容器作为 L2 标签:
      - **投放单元原则**：L2 粒度应等同于**广告定向的”圈选词”**（如”养猫人群”、”主机玩家”），拒绝细碎的下位词或发散性话题。
      - **高内聚低耦合**：遇到语义近似的词，必须统一使用**最简短、最通用**的标准词汇。
      - **容器隔离**：根据实体性质建立 L2 容器：
        - [WORKS] 作品容器 (如”必追好剧”) -> L3 填书/影/音名。
        - [PERSON] 人物容器 (如”喜爱演员”) -> L3 填人名。
        - [PRODUCT] 产品容器 (如”数码装备”) -> L3 填型号/品类。

    3.2 **L3 归叶 (Leafing)**：在 L2 下填充具体实体：
        - 优先从 Candidates 中匹配。
        - 如果 L2 成立但无具体 L3，L3 列表可为空。

4. **置信度评分 (Confidence Scoring)**
    请对树的**每一个节点**进行独立评分：
    - **High**: 核心兴趣。有明确行为（购买、持有、高频讨论）或强烈的身份认同。
    - **Medium-High**: 重要兴趣。逻辑推演严密，上下文证据充分。
    - **Medium**: 一般兴趣/泛关注。
    - **Medium-Low**: 弱信号。
    - **Low**: 证据不足。
